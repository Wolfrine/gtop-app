# GTOP design memory

GTOP uses Central's shared UI/UX method:

- `Wolfrine/Central/design/UI_AGENT_PROTOCOL.md`
- `Wolfrine/Central/design/EXECUTION_ROUTING.md`

Keep this folder as GTOP's compact, project-specific design contract. Do not copy the Central knowledge base here.

## Surface targets

| Surface | Default level | Intent |
|---|---|---|
| Admin / question-bank tools | L1–L2 | Dense but clear, fast and operational |
| Student dashboard / practice flows | L2–L3 | Polished, motivating, low-friction |
| Live quiz / Challenge Arena | L3 with selective L4 | Energetic interaction with meaningful motion |
| Public landing / conversion surfaces | L3–L4 | Distinctive GTOP identity, trust and strong story |

## Execution rule

Route by evidence needed rather than code size. Deterministic edits may use Chat + GitHub. If a change depends on visual judgment, use a running-browser/Codex loop and verify desktop + mobile before completion. Work is for larger reference research or design audit before implementation.

A build passing is not a visual acceptance gate.

Local decisions and review notes for the question-paper builder are in `QUESTION_PAPER_UI.md`. Add new local notes only when they capture a durable GTOP-specific decision, rejection, or review lesson.
