# V1 UI rollout — 5 September 2026

The founder approved incremental presentation improvements on the existing V1, with small commits going directly to main. V2 is not part of this work.

## Verification method

- Existing V1 baseline: `3893926975caa16af9ca623afb130283e8703de6`.
- Production build for every application patch, retaining the existing 3 MB total and 4 KB per-component error budgets.
- `GTOP_UI_BASE_REF=<baseline> node gtop-app/scripts/ui-contracts.test.cjs` compares event bindings, route targets, structural conditions, inputs and application TypeScript. The only application TypeScript edit is sidebar labels/tooltips. The admin review tool is explicitly separate. The Admin Console active marker now matches its route exactly to avoid announcing two current pages; destinations and visibility are unchanged.
- Native answer buttons add only `type=button` and an ARIA binding for the existing selection state. Their existing selection handler, live-mode freeze checks and progression remain unchanged.
- Review the actual signed-in V1 via its admin UI Preview, including real 360/390/768/1024 px iframe viewports. This tests CSS and browser interactions, not physical device keyboards or performance.
- A temporary `codex/v1-ui-review` deployment ref points to each candidate commit. After review, that exact commit advances main with a non-forced fast-forward. There is no separate product implementation or V2 branch in this rollout.
- Production deployment must succeed and the served asset version must match before the next application release.

## Existing issues kept separate

- Action Plan reads are denied by the deployed Firestore rules even for the signed-in administrator. This prevents writing its execution tracker; these repository notes provide the delivery record.
- The existing update prompt advertises v2.0.2 while V1 is live. Its version source and refresh logic were not changed.
- Older open tabs may retain the service-worker build. Deployment review uses the existing Reload action with navigation completion and checks script filenames.
- The dashboard's Last Score disagrees with the latest dated attempt in Progress for the reviewed account. The existing dashboard selects the last array entry while recent attempts are separately date-sorted. The calculation is unchanged.
- The custom quiz difficulty selection exists, but the existing start action does not pass it to the quiz route. Removing the AI wording does not implement adaptive difficulty.
- Admin Console Add MCQs and Quick Quiz shortcuts are existing console-log placeholders, confirmed against the baseline TypeScript. Manage MCQs → Add MCQs works; the shortcut handlers were preserved.
