# Private conversational Question Paper pilot

Approved24October2026 in task `01a1683d-9c29-7a43-8238-207c0e380d79`; Action Plan `QndHjDJw0x3wzzG5szwW`. This supersedes the earlier discovery-only stage for the scoped pilot. GTOP core, legacy access/data and the stopped old scheduler are preserved. Migration and retirement remain later decisions.

The independent Angular application is `question-papers/`. Firebase Hosting site `gtop-question-papers` forwards `/api` to `gtopAssistantGateway`. The gateway checks existing Firebase identity, current admin role and a private two-person allowlist. Browser clients have no direct assistant Firestore permissions. Worker custom claims are excluded from legacy Firestore and Realtime Database signed-in access. Release audits Storage policy before pairing can be used. Existing human role behavior is regression-tested.

The Windows controller at `tools/gtop-assistant/` uses loopback Ollama/Qwen3.5 4B for ordinary conversation and the installed ChatGPT-authenticated Codex CLI for generation/revision and separate content review. It makes outbound gateway requests; there is no public PC/Ollama endpoint, separate OpenAI API key, paid-API fallback or Codex fork. The controller supports Node22; this PC's bundled Node24 is used without changing its global runtime.

The server owns messages, access, original hashes, task roots, leases, retries, cancellation, revisions and publication. Original paper request, current correction, relevant history, fallible local interpretation, source data and verified requirements travel together. New generations after clarification preserve the source-identified task root. A revision inherits its original paper root. Single-question revisions copy all other content and independently compare question placement, section metadata, marks/type/chapter and original-content hashes.

Generation → structural validation → independent Codex content review → at most one correction → final review if corrected → private delivery. A structural repair consumes that same correction allowance. Unresolved review findings stop publication. Structural checks cover strict shapes, all ten chapters, exact attempted marks, whole-question OR alternatives, objective options, duplicate stems, worked answers, pinned sources and KaTeX rendering. They establish interface/content consistency, not teacher acceptance. The source PDF SHA256 is `5610f09d357d3ccc9a7b39fc29cb7b1f4530847753783b16c72fff691acd2418`; source facts live in `assistant-service/domain/curriculum.mjs`.

Printable question and answer HTML are separate, escaped, script-free and privately delivered. KaTeX/mhchem notation and fonts are self-contained. HTML is gzip-stored in Firestore with verified raw size/SHA; this accommodates math-heavy answers without adding object-storage infrastructure. Maximum raw artifact4MiB, compressed record below safe Firestore size. Browser Print/Save PDF is the first delivery format; immutable prior versions remain retrievable.

The release workflow runs backend/domain/controller/UI checks, real isolated emulator identity/job/rule tests and existing shared-rule regressions. An exact source-diff guard prevents core deployment for assistant-only changes plus the specific worker-claim restrictions. Drift or broader application/rule changes fail the narrow classification. Protected backend/production environments and existing Actions Firebase identity remain in place. Only the independent Hosting site, new gateway and narrowly restricted rules are released. No IAM repair is automatic.

No bank connector, attachments, central launcher, scanning, generalized agent framework or automated self-improvement is included. Browser privacy, human content review and actual classroom feedback remain operational responsibilities.
