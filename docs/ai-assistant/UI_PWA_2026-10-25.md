# GT Papers compact UI and independent PWA

Sachit authorized this UI pass after reporting clutter, oversized chat text and excessive whitespace. Scope is the independent Question Papers frontend. Local-model behavior, controller, gateway, data, GTOP core and the stopped legacy scheduler are outside this change.

## Result

- Compact 60px desktop / 58px phone app header; quieter rail and conversation context.
- Chat uses 14.5px/23.2px on desktop and 15px/24px on phones, with an 80ch maximum reading measure. The phone input remains 16px to avoid unwanted browser zoom.
- One clear inline paper card with View paper, Answers and Revise. Feedback and earlier revisions are disclosed when needed. Supporting text contrast was corrected without inflating type.
- Mobile library search stays visible; board/class/subject filters expand on demand and retain a full active-scope summary. Existing loaded-page filtering remains explicit.
- Papers and answers still open independently with print controls. Existing ownership, read-only library access, immutable revisions, escaping and maths presentation remain in place.
- The avatar indicates the signed-in user. Sign out is an explicit rail/drawer action. Reply-in-progress text distinguishes drafting from being able to send.

Three direction studies and five substantive implementation/review rounds are recorded in [the design review](../../design/assistant-pilot/ui-density-2026-10-25/REVIEW.md). Direction studies are synthetic concepts; actual-app browser checks use clearly labelled synthetic fixtures. They do not establish educational correctness or intended-user acceptance.

## PWA

GT Papers has its own manifest, standalone identity, navy theme, generated logo, favicon, Apple touch icon and 192/512px maskable icons on its existing independent Hosting origin. [Asset provenance and exact prompt](../../design/assistant-pilot/ui-density-2026-10-25/assets/README.md) are retained with the source image.

The matching Angular 21.2.25 service worker is production-only. It prefetches 30 public shell files: index, scripts/styles, manifest, icons, public browser configuration and local KaTeX fonts. There are no data cache groups or remote resource patterns. API and Firebase Authentication helper paths are excluded from navigation fallback. Conversations, jobs, private artifacts and authenticated API responses are never added to the service-worker cache by this configuration.

Install uses the browser's native prompt when available and otherwise shows browser/Safari instructions. It is hidden in detected standalone mode. Updates are offered explicitly and never force a reload. A nonempty message draft blocks the update action and stays intact. Close/Escape returns focus to the install/update trigger. Online/offline indication uses browser connection events; it does not infer that the PC worker is available.

Installation does not provide offline conversation or paper creation. The cached public shell can open when the origin is unavailable; private work still requires connectivity and the running controller. The existing Firebase sign-in and permission model remains authoritative.
