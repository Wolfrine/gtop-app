# Paper register release gate

Original `paperConversations`, `paperRequests`, `paperMessages`, `paperDrafts` and immutable artifacts remain authoritative. This release adds a derived register and source-word index. It does not migrate, delete or fabricate original requirements or pause the scheduled worker.

## Deployment order

Use the protected `firebase-v2-backend.yml` workflow with `deploy_backend=true`, `deployment_scope=paper-chat-backend`, and the reviewed rules-change flag. It validates rules and publication/register integrations, deploys additive rules/indexes and the reviewed functions, then backfills and verifies historical sources before live verification. Hosting must wait for a successful backend gate and `paperRegisterState/v1.ready === true` for the current schema.

The backfill step runs `node backfill-register.mjs --live-derived-index --until-ready` in `gtop-app/functions`. It resumes the stored checkpoint automatically in passes of at most 10,000 source/projection checks. Defaults: 30 passes and a 40-minute overall budget checked before starting each pass; the protected step has a 45-minute timeout. Checkpoints are retained every bounded page (100 documents). A timeout, failed request, exhausted budget or exit code 2 is incomplete, not success. Rerun the same protected workflow/command to resume; do not use `--restart` for recovery. No hosting promotion is allowed until verification reports ready.

Configuration: `REGISTER_BACKFILL_BUDGET` (1–10,000), `REGISTER_BACKFILL_MAX_PASSES` (1–100), `REGISTER_BACKFILL_MAX_MS` (1–7,200,000). The default single-pass command remains available without `--until-ready`. `backfill-cli.integration.mjs` verifies an interrupted pass, automatic multi-pass continuation and unchanged source documents against an isolated emulator project.

Live datastore access uses short-lived delegation to the existing `78765581239-compute@developer.gserviceaccount.com` runtime identity with the datastore scope. Existing deployment ADC is only the refreshable impersonation source; it is not used directly for derived writes. An existing `ACCESS_TOKEN` is the fallback for manual protected execution. No new IAM grants or permanent credentials are created.

## Read and cache boundaries

`GET /register` requires a currently authenticated admin. It returns at most 30 families, a filter/identity-bound opaque cursor, the readiness flag, and whether scanning can continue. Search uses at most 8 whole words/240 characters across historical titles, requirements, academic metadata and IDs. Each request scans at most 200 source candidates and reads at most 200 lightweight summaries plus the readiness document; repeated source matches can produce a continuation page with no new family. Continue using its cursor until exhausted. This is word retrieval, not substring or semantic search.

Unsearched first pages use bounded Firestore listeners and the existing persistent cache. Gateway first-page cache retains at most eight queries per current admin. A tab retains at most ten loaded gateway pages (at most 300 lightweight rows) and the cursor before that window for return navigation. Returning renders the cached window then revalidates those bounded pages. Query/view/mine context travels in the URL; a bare register URL selects All. Permission denial, sign-out or role loss clears privileged visible state and that admin's gateway/return cache. Typed unsent drafts remain account-scoped on the device and do not claim server acknowledgement.

Detail listeners retain one conversation, 150 recent messages, 100 requests and 20 papers; explicit history reads fetch up to 50 earlier messages/requests or 20 earlier versions per action. Saved HTML and separate key remain immutable. Browser Print/Save PDF is the supported export.
