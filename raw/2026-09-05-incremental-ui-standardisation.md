# Raw Note - 2026-09-05 - Incremental UI Standardisation

## Source

Founder discussion after publishing Learning Lab to V1. The founder reported repeated unsuccessful UI improvements and V2 functional issues, proposed standardising V1 through small changes directly on main, and approved the detailed visual/content improvement list with "Okay go ahead."

## Context

The approved goal is a coherent, welcoming learning product that preserves working functionality. Existing tokens, styles and the UI preview are the foundation. Observed issues include mixed visual styles, uneven hierarchy, inconsistent names, excessive promotional copy and outdated public text.

## Key Points

- Improve theme, colours, typography, placement, layout, spacing, navigation, naming, content, controls, forms, data presentation, icons, feedback states, responsiveness and accessibility.
- Keep the established blue identity and light surfaces, using other colours deliberately.
- Preserve feature behaviour, account access, calculations and saved data.
- Validate actual interactions and responsive rendering; a small diff or successful build alone cannot establish usability.
- Keep product descriptions factual and names consistent.

## Decisions

- Improve the existing V1 experience incrementally.
- Commit and publish small verified changes directly to main, checking each deployment before the next visual change.
- Preserve useful lesson-specific visuals within shared presentation rules.

## Open Questions

- Further refinement should follow feedback on the deployed improvements.

## Suggested Wiki Integration

- Decisions: preserve working practice while improving presentation and language.
