# Raw Note - 2026-09-29 - Admin Question Module

## Source
Founder request in ChatGPT Work on 2026-09-29 and implementation review.

## Context
Admins find the question module complex, especially on phones. Paper creation and the paper tab in other question tools feel like separate products. The journey is unclear and omits chapter-wise non-objective bank management.

## Key Points
- Reduce admin workload across creation, bank maintenance, review, requests and return to the finished paper. Consistent navigation is necessary but does not replace a complete journey.
- Chapter-wise written questions need the same discoverability and maintenance attention as objective questions.
- The scheduled creator must honor actual shortages, pending review and explicit admin demand, with safe continuation across runs.
- Internal activity evidence should identify areas, actions, active time and actor identity for product improvement. It must not add another admin dashboard or routine reporting burden.
- Reporting may be weekly or monthly at most. Monthly was selected for the existing operating routine; no behavior claims exist before actual usage arrives.

## Decisions
- A single Questions & papers module with Papers, Bank, Review and Requests; the builder uses format, syllabus, coverage and preview steps on every device.
- Keep saved papers stable and make returning to a request explicit. Generated questions always need review.
- Use private coarse activity aggregates and approximate active time; exclude typed content and question text. Do not interpret time as productivity or learning quality.

## Open Questions
- Which steps cause real abandonment or repeated corrections after release? Assess with observed usage and admin feedback.
