# GTOP local controller

Node22-compatible TypeScript controller. The installed Node24 runtime also passes local checks. This is a closed educational workflow, not a general shell agent.

Run `npm ci`, `npm run check`, `npm test`. Start manually with `./start-worker.ps1 -Config H:\GTOP-Local-AI\pilot-runtime\worker.json`. The launcher creates a hidden process, checks for duplicates and records its PID/log paths. It does not install a service, alter global environment variables, or change a scheduled task. Keep this PC awake and connected for the private pilot. Inspect `process.json` and the process command line before stopping that controller; never stop unrelated Codex/Ollama or scheduled processes.

The private config contains gateway, workerId, Firebase public apiKey, loopback Ollama URL/model, absolute Codex executable/model and a private dataDirectory. Production pairing uses `secretProtected`, created with Windows `ConvertFrom-SecureString` under the current Windows user. The server stores only its SHA256. Never commit this file or print the decrypted secret. The pilot's existing private config lives outside the repo on H:. Do not copy Codex authentication files. `codex login status` must say ChatGPT. The CLI child receives an environment allowlist excluding API keys and worker credentials, uses existing subscription authentication, read-only sandbox and disabled tools/plugins. There is no paid-API fallback.

For isolated integration only, a loopback config can use `authEmulator` and `emulatorSecret`. Production endpoints reject that configuration. Local UI's `?emulator=1` is compiled as a localhost-only emulator selection; production fixture code is excluded. No login bypass is shipped.

Two outbound claim loops keep local conversation independent of one Codex paper pipeline. Empty claims return immediately; the PC waits five seconds before polling again, avoiding continuously held billable gateway requests. Worker heartbeat30s, leases120s; stale delivery is refused server-side. Cancellation fences publication immediately; local requests/CLI termination follows the heartbeat within30s. Each Codex stage has a15-minute limit. A worker interruption needs explicit retry; it never automatically reruns an expensive paper. A reviewed retained result is bound to owner, original request hashes, requirements, operation and base hash, then revalidated before retry delivery. Otherwise retry starts fresh.

Private per-job records preserve original server payload, local prompts/raw responses, controller decisions, skill hashes, Codex prompts/schemas/events/results, measured stage durations, validation and delivery. These may contain private conversation content. They remain on H:; repository examples are explicitly synthetic-user integration evidence. No automatic prompt rewriting/training occurs.

Context uses recent relevant conversation, explicit quoted preferences and owned paper data. The entire local prompt plus schema uses a conservative byte budget within8K context, reserving output space. Oversized requests may be represented by a marked excerpt locally; full original text and hashes remain in the Codex handoff. A small-model interpretation never replaces that original. Paper languages differ from conversation language. Legacy saved school/class/lab fields are excluded.

Capabilities are versioned create/revise/explain instructions, pinned syllabus lookup, owned-question lookup, actual status and bounded arithmetic. No arbitrary tool names, shell strings or model-written permissions execute. The gateway supports only create/revise paper work; development, deployment, destructive operations and bank writes are unavailable. Simple paper explanations are local assistance, not independent academic approval.

Current content scope: configured GTOP boards and appropriate programmes, Classes5–12, original practice papers10–100marks (default80), English/Hindi document language. Saved and officially checked curriculum availability differ. Programme/level/code/cohort ambiguity must be resolved; an online check runs only on request. Full syllabus or explicitly selected chapters are supported, covering all topics within those chapters. Attempt every numbered question, with whole-question OR choices only. Section-level selective attempts remain unsupported. Custom mark totals must not be presented as official board formats. Academic acceptance remains with the teacher.

Harness version3 persists a conversation-local task brief and source-message references before a paper exists. It retains selected chapters, all-topic coverage, marks, languages, duration, outstanding clarification and creation hold/resume state. The gateway rebuilds the brief from saved user messages and independently checks any model-selected quotation. Chapter restrictions survive delegation and constrain both the curriculum snapshot and publication validator; switching coverage requires a new paper. A discussion of a board is not a selection, and a paused request cannot resume merely because a scope value is mentioned later.

The local adapter preserves user/assistant message roles, keeps the latest request last, supplies compact controller facts and asks only for reply/action on ordinary turns. Optional chapter extraction includes exact user quotations. Non-thinking conversation uses temperature0.7/top-p0.8/top-k20 and at most700 output tokens in the existing8K window; no model weights changed. Invalid JSON gets one bounded repair with actual prior output. Claimed Codex starts/progress are replaced with controller facts. Exact logs and timings stay private; see the [harness release record](../../docs/ai-assistant/HARNESS_IMPROVEMENTS_2026-10-25.md).
